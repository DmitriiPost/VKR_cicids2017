# CICIDS2017: как подготовлены данные

## 1. Набор данных

CICIDS2017 (Sharafaldin, Lashkari, Ghorbani, ICISSP 2018): 5 дней (3–7 июля 2017) сетевого трафика синтетической корпоративной сети. Норма генерируется по профилям 25 пользователей, атаки реальные. Трафик разобран в потоки программой CICFlowMeter. Использован архив `GeneratedLabelledFlows` (с IP и временем), в нём 8 CSV. Архив `MachineLearningCSV` — те же числовые строки без идентификаторов, `Protocol` и времени.

## 2. Что сделано с данными

**Очистка (`01_clean.py`):**
1. Прочитаны 8 CSV, из названий колонок убраны пробелы.
2. Удалены полностью пустые строки: 288 602 в `Thursday-…WebAttacks`.
3. Удалена колонка `Fwd Header Length.1` (копия `Fwd Header Length`).
4. Метки приведены к единому виду (`Web Attack � XSS` → `Web Attack - XSS`).
5. Разобрано время. У понедельника формат с секундами, у остальных дней без; AM/PM в файлах нет, поэтому часы 1–7 переведены в 13–19. Результат сверял с расписанием атак на странице датасета.
6. `inf` заменены на NaN (4 376 ячеек). Физически невозможные отрицательные значения (`Flow Duration`, интервалы `Flow IAT *`, `Fwd IAT Min`, длины заголовков, `min_seg_size_forward`) заменены на NaN.
7. Посчитаны хэши строк: с меткой (для дубликатов) и без метки (для конфликтов).

После очистки: **2 830 743 потока**, 5 792 из них содержат NaN (0.2%; у Heartbleed 4 из 11), поэтому строки с NaN не удалялись.

**Фильтр перед разбиением (`03_make_splits.py`):**
8. Удалены 7 018 потоков-конфликтов (одинаковые признаки, разные метки; пары BENIGN-PortScan, Hulk, DDoS, slowloris).
9. Удалены 302 527 точных дубликатов (признаки и метка совпали; больше всего у SSH-Patator 45%, PortScan 43%, FTP-Patator 25%, Hulk 25%).

Осталось **2 521 198 потоков**. Потоки вне официальных окон атак (Bot 24%, SSH-Patator 7.5%) сознательно не отбрасывались.

**Предобработка признаков (`04_make_arrays.py`, все статистики считаются только по train):**
10. Убраны идентификаторы, IP, `Source Port`, время, `Protocol` и `Destination Port` (т.к. они выдают класс).
11. Убраны 8 колонок, постоянных на train (`Bwd PSH/URG Flags`, шесть `*Bulk*`). Осталось **68 признаков**.
12. NaN заменены медианой train.
13. Для 56 колонок с очень длинным хвостом применён `sign(x)·log1p|x|`.
14. MinMax-масштабирование в [0,1] по train; val и test обрезаются до [0,1].
15. Метки: 15 классов (`labels=full`). Train ограничен 20 000 потоков на класс (seed 0); val и test оставлены в естественном распределении.

## 4. Разбиение train / val / test

**Какие варианты рассматривались.** Реализованы три (A, C, F), остальные отклонены с обоснованием.

| Метка | Вариант | Идея | Статус |
|---|---|---|---|
| **A** | случайное | стратифицированное по меткам 70/15/15 | реализован (`--protocol random`), для сравнения с литературой |
| **B** | случайное после удаления дубликатов | как A, но почти одинаковые потоки не должны попадать в разные части | отдельно не реализован: фильтр дубликатов и конфликтов теперь входит во все протоколы (флаги `--no-dedup`, `--keep-conflicts` отключают его; сырое A = A с этими флагами) |
| **C** | блоки по времени | внутри (день, класс) смежные блоки train / val / test по минутам, зазор на границах | реализован (`--protocol time`), **основной** |
| **D** | по группам IP | потоки одного источника или пары IP целиком в одной части | отклонён: почти все атаки идут с одного IP `172.16.0.1` на `192.168.10.50` (99.4% потоков с этого адреса — атаки), группы разнесли бы целые классы по разным частям |
| **E** | по дням | например train пн–ср, test чт–пт | отклонён: каждая атака есть только в одном дне (см. таблицу классов), в train или test не оказалось бы целых классов |
| **F** | leave-one-family-out | выбранное семейство атак целиком в test, в train и val его нет | реализован (`--protocol lofo --holdout ...`), отдельный эксперимент про невиданные атаки |

В итоге для основных результатов используются **C** (честная оценка) и **A** (сравнение с литературой), F подключается по необходимости.

### Протокол C («блоки по времени»), основной

Внутри каждой пары (день, класс) потоки упорядочены по минутам и разрезаны на три смежных блока: первые 70% — train, следующие 15% — val, последние 15% — test. Первая минута после каждой границы пропускается (`gap`), если у пары не менее 10 активных минут.

*Для чего:* Атака вроде Hulk за 21 минуту шлёт десятки тысяч почти одинаковых потоков. При случайном разбиении у каждого тестового потока в обучении найдётся почти копия, и модель не учится распознавать атаку, а узнаёт знакомое. При блочном разбиении модель учится на начале атаки и проверяется на её продолжении. Проверка: доля тестовых минут атак, которые есть и в train, при случайном разбиении 1.000, при блочном 0.000.

Train — обучение; val — подбор гиперпараметров (для SCN: `r`, набор `λ`, `L_max`, `T_max`, окно `K`; для RF: число деревьев и глубина); test — одна финальная оценка. Метрики считать по каждому классу и macro-F1, а не по одной accuracy (из-за 80% BENIGN).

## 5. Ограничения

- **Редкие классы.** У SQL-инъекций val пуст (окно 3 минуты), у Heartbleed в val и test 1 и 2 потока, у Infiltration 5 и 4. Метрики по ним шумные; их стоит отдельно помечать или исключать из агрегатов.
- **PortScan.** Почти все потоки (89 919 из 90 255) приходятся на фазу 14:51–15:29, где шли разные виды nmap-сканов по 2–3 минуты. Блочный протокол кладёт в train в основном первые виды, в test остальные, то есть проверяет ещё и обобщение на новые типы сканирования. Val у PortScan — одна минута (14:55).
- **Потоки вне окон.** У Bot 473 из 1 966 и у SSH-Patator 443 из 5 897 потоков лежат вне официального окна атаки (допуск +-5 минут); Они оставлены в данных.
